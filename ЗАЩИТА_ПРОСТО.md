# Подготовка к защите: всё очень просто

## 1. Что мы вообще сделали?

Представь, что у нас есть записка, написанная по особым правилам. Например:

```text
$[age: 7, sizes: {1, 2, 3}]
```

Компьютер пока не понимает, что с этой запиской делать. Наша программа читает
её, проверяет и переписывает в другом формате — XML.

То есть мы сделали **переводчика**:

```text
записка на учебном языке → наш переводчик → XML-записка
```

На вход программа получает один файл. На выходе создаёт другой файл.

---

## 2. Зачем это нужно?

Разные программы могут хранить настройки в разных форматах. Чтобы другая
программа смогла прочитать наши настройки, мы превращаем их в понятный и
строгий XML.

Заодно наша программа проверяет, нет ли в записке ошибок. Если человек забыл
скобку или запятую, программа не молча ломается, а пишет, где ошибка.

---

## 3. Из чего состоит наш язык?

В языке есть всего несколько деталей. Как в конструкторе.

### Число

Это самая простая деталь:

```text
42
```

Можно использовать только целые неотрицательные числа: `0`, `1`, `2`, `100` и
так далее. Число `-5` по правилам задания использовать нельзя.

### Массив

Массив — это коробка, в которой несколько вещей лежат по порядку.

```text
{10, 20, 30}
```

Здесь в коробке лежат три числа. Сначала `10`, потом `20`, потом `30`.

В коробку можно положить другую коробку:

```text
{1, {2, 3}}
```

Это и называется **вложенность**.

Пустая коробка тоже разрешена:

```text
{}
```

### Словарь

Словарь — это шкаф с подписанными полочками.

```text
$[width: 100, height: 200]
```

Здесь:

- на полочке `width` лежит число `100`;
- на полочке `height` лежит число `200`.

Имя полочки пишется маленькими латинскими буквами. Например, `server`, `value`
или `ports`.

На полочку можно положить не только число, но и коробку или другой шкаф:

```text
$[server: $[ports: {80, 443}]]
```

Получается шкаф внутри шкафа, а внутри него ещё и коробка. Наша программа
умеет разбирать такие конструкции на любой глубине, пока хватает памяти.

Пустой словарь тоже разрешён:

```text
$[]
```

### Константа

Константа — это как стикер с именем, на который мы записали готовое значение.

```text
var timeout = 30
```

Мы сказали: «Запомни: `timeout` означает `30`».

Теперь вместо числа можно использовать имя:

```text
@(timeout)
```

Программа увидит этот стикер и подставит вместо него `30`.

Константа может хранить не только число:

```text
var ports = {80, 443}
```

Теперь `@(ports)` означает целый массив `{80, 443}`.

Важное правило: сначала нужно сделать стикер, а только потом им пользоваться.
Нельзя написать `@(ports)`, если объявления `var ports = ...` ещё не было.

## 4. Пример целиком

Допустим, у нас есть такой файл:

```text
var timeout = 30
var ports = {8080, 8443}
$[
  server: $[
    ports: @(ports),
    limits: {100, @(timeout)}
  ],
  enabled: 1
]
```

Что здесь написано простыми словами?

1. Запомни число `30` под именем `timeout`.
2. Запомни два порта под именем `ports`.
3. Создай главный словарь.
4. Внутри него создай описание сервера.
5. В описание сервера подставь сохранённые порты.
6. В ограничения подставь сохранённое время ожидания.
7. Добавь признак `enabled` со значением `1`.

После работы программы получится XML. Его небольшой фрагмент выглядит так:

```xml
<entry name="ports">
  <array>
    <number>8080</number>
    <number>8443</number>
  </array>
</entry>
```

Здесь видно, что имени `ports` соответствует массив из двух чисел.

Сами объявления `var` в итоговый XML не попадают. Они нужны только во время
перевода. В XML попадает уже готовый результат.

## 5. Как программа понимает записку?

Программа работает по шагам.

### Шаг 1. Получает имена файлов

Человек говорит:

- откуда читать;
- куда записывать результат.

Например:

```bash
./run.sh --input examples/webserver.cfg --output output.xml
```

Здесь `webserver.cfg` — вход, а `output.xml` — результат.

### Шаг 2. Читает входной файл

Программа берёт весь текст из файла. Файл должен быть в кодировке UTF-8.

### Шаг 3. Проверяет правила языка

Для этого используется библиотека **Lark**.

Можно представить Lark как очень внимательного проверяющего. Мы дали ему
список правил:

- как выглядит число;
- как выглядит имя;
- где должны стоять скобки;
- где нужны запятые;
- как записываются константы.

Lark проверяет текст по этим правилам и строит из него дерево.

Дерево — это как разбор предложения на части. Например, становится понятно,
что словарь находится внутри массива, а число находится внутри словаря.

### Шаг 4. Превращает текст в понятные Python-значения

После проверки:

- число становится Python `int`;
- массив становится Python `list`;
- словарь становится Python `dict`.

Одновременно программа запоминает константы и подставляет их значения.

### Шаг 5. Делает XML

Теперь программа проходит по готовым значениям:

- число превращает в `<number>`;
- массив превращает в `<array>`;
- словарь превращает в `<dictionary>`;
- каждую пару «имя и значение» превращает в `<entry name="...">`.

Снаружи всего документа находится один главный элемент `<config>`.

### Шаг 6. Записывает результат

Готовый XML сохраняется в указанный файл. Если папки для результата ещё нет,
программа её создаёт.

## 6. Что происходит при ошибке?

Допустим, человек написал:

```text
{1, 2
```

Он забыл закрывающую `}`.

Программа остановится и напишет примерно такое:

```text
Ошибка: Синтаксическая ошибка: строка 1, столбец 6. Ожидалось: ...
```

То есть она сообщает:

- что это синтаксическая ошибка;
- в какой строке она находится;
- в каком столбце;
- что программа ожидала увидеть.

Программа также замечает другие ошибки:

- константа используется до объявления;
- одна и та же константа объявлена дважды;
- в одном словаре два одинаковых ключа;
- входного файла не существует.

Если преобразование не удалось, новый XML не создаётся. Код завершения будет
`1`. При успехе код завершения — `0`.

## 7. Зачем нужны тесты?

Тесты — это маленькие автоматические проверки.

Мы заранее говорим программе:

> Если на вход дать `{1, 2}`, то внутри должен получиться список `[1, 2]`.

Потом другой тест проверяет словарь, следующий — константу, ещё один — ошибку
и так далее.

Всего у нас **31 тест**. Они проверяют:

- числа;
- массивы;
- словари;
- вложенные конструкции;
- пустые коллекции;
- константы;
- ошибки;
- XML;
- командную строку;
- оба больших примера.

Это нужно, чтобы изменение одной части программы незаметно не сломало другую.

## 8. Что лежит в папках?

Очень коротко:

- `src/` — сама программа;
- `tests/` — автоматические проверки;
- `examples/` — две готовые записки на нашем языке;
- `run.sh` — кнопка запуска;
- `README.md` — инструкция для человека;
- `pyproject.toml` — список нужных библиотек и настроек;
- `.gitignore` — список мусора, который не нужно отправлять в GitHub.

В `examples/` есть:

1. `webserver.cfg` — настройки воображаемого веб-сервера.
2. `library.cfg` — настройки воображаемой библиотеки.

Это две разные предметные области, как и требовалось в задании.

## 9. Как показать работу на защите?

### Показать успешный перевод

```bash
./run.sh -i examples/webserver.cfg -o output.xml
```

После этого открыть `output.xml` и показать элементы `config`, `dictionary`,
`entry`, `array` и `number`.

### Показать второй пример

```bash
./run.sh -i examples/library.cfg -o library.xml
```

### Показать тесты

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Если виртуальное окружение уже активировано, достаточно:

```bash
python -m unittest discover -s tests -v
```

В конце должно быть написано `OK`.

## 10. Простые ответы на вопросы преподавателя

**Почему программа называется транслятором?**  
Потому что она переводит текст из одного формата в другой: из учебного языка в
XML.

**Почему использовали Lark?**  
Потому что в задании обязательно нужен специализированный инструмент
синтаксического разбора. Lark читает грамматику и помогает разбирать текст по
правилам, а не вручную символ за символом.

**Что такое грамматика?**  
Это список правил, по которым можно узнать, правильно ли записан язык.

**Что такое константа?**  
Это именованное значение. Мы один раз его объявляем и потом используем по
имени.

**Что делает `@(name)`?**  
Берёт ранее объявленную константу `name` и подставляет её значение.

**Почему объявлений `var` нет в XML?**  
Потому что они нужны только на этапе трансляции. В результат записывается
вычисленная конфигурация.

**Почему в примерах нет строк вроде `"localhost"`?**  
Потому что строки не входят в язык из задания. Разрешены только числа, массивы
и словари.

**Поддерживаются ли пустые массивы и словари?**  
Да, `{}` и `$[]` разбираются и преобразуются в пустые XML-элементы.

**Что будет, если дважды объявить константу?**  
Программа сообщит об ошибке и остановит преобразование.

**Что будет, если написать отрицательное число?**  
Будет синтаксическая ошибка, потому что в задании числа описаны как `\d+`.

**Зачем нужен `run.sh`?**  
Он позволяет запускать проект одной короткой командой и сам выбирает Python из
виртуального окружения.
