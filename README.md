# Учебный конфигурационный язык → XML

## 1. Общее описание

`config2xml` — инструмент командной строки для варианта №4. Он читает файл
на учебном конфигурационном языке, вычисляет константы на этапе трансляции и
сохраняет результат в XML. Синтаксический разбор выполняется с помощью
специализированной библиотеки **Lark** по LALR-грамматике из
`src/config_converter/parser.py`.

Поддерживаются:

- неотрицательные целые числа (`\d+`);
- имена из строчных латинских букв (`[a-z]+`);
- массивы `{1, 2, 3}`, включая вложенные и пустые;
- словари `$[first: 1, second: {2, 3}]`, включая вложенные и пустые;
- объявления констант `var name = значение`;
- ссылки на константы `@(name)` в любом месте значения.

Файл содержит ноль или несколько объявлений, а затем одно итоговое значение.
Объявления не попадают в XML: в документ записывается только итоговое значение
с подставленными константами. Константа должна быть объявлена до использования.
Повторные имена констант и повторные ключи одного словаря запрещены. Запятая
после последнего элемента не допускается. Пробелы и переводы строк незначимы.

## 2. Установка и сборка

Требуется Python 3.10 или новее. В macOS и Linux выполните:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e ".[dev]"
```

Команда устанавливает Lark, консольную команду `config2xml` и инструменты для
проверки проекта. Сборка wheel и sdist выполняется так:

```bash
python -m build
```

Результат появляется в каталоге `dist/`, который исключён из Git.

## 3. Запуск и настройки CLI

Через скрипт из корня репозитория:

```bash
./run.sh --input examples/webserver.cfg --output output.xml
```

`run.sh` использует `.venv/bin/python`, если виртуальное окружение существует,
иначе — `python3` или интерпретатор из переменной окружения `PYTHON`.
После установки пакета доступны равнозначные команды:

```bash
config2xml -i examples/library.cfg -o output.xml
python -m config_converter -i examples/library.cfg -o output.xml
```

Аргументы командной строки:

| Аргумент | Обязательность | Назначение |
| --- | --- | --- |
| `-i`, `--input` | да | Путь к исходному файлу в кодировке UTF-8. |
| `-o`, `--output` | да | Путь к XML-файлу в кодировке UTF-8. |
| `-h`, `--help` | нет | Показать справку и завершить работу. |

Недостающие родительские каталоги для результата создаются автоматически.
Успешное преобразование возвращает код `0`. Ошибка файла, синтаксиса или
константы выводится в `stderr` и возвращает код `1`; XML при этом не создаётся.
Ошибка в аргументах команды возвращает стандартный код `2`.

## 4. Синтаксис языка

```text
start       = const_decl* value
const_decl  = "var" NAME "=" value
value       = NUMBER | array | dictionary | const_ref
array       = "{" [value ("," value)*] "}"
dictionary  = "$[" [entry ("," entry)*] "]"
entry       = NAME ":" value
const_ref   = "@(" NAME ")"
NUMBER      = \d+
NAME        = [a-z]+
```

Пример с константами и вложенностью:

```text
var timeout = 30
var ports = {8080, 8443}
$[
  server: $[
    ports: @(ports),
    limits: {100, @(timeout)}
  ],
  enabled: 1
]
```

Результат:

```xml
<?xml version="1.0" encoding="utf-8"?>
<config>
  <dictionary>
    <entry name="server">
      <dictionary>
        <entry name="ports">
          <array>
            <number>8080</number>
            <number>8443</number>
          </array>
        </entry>
        <entry name="limits">
          <array>
            <number>100</number>
            <number>30</number>
          </array>
        </entry>
      </dictionary>
    </entry>
    <entry name="enabled">
      <number>1</number>
    </entry>
  </dictionary>
</config>
```

Правила представления в XML:

| Значение языка | XML |
| --- | --- |
| Число | `<number>123</number>` |
| Массив | `<array>` с дочерними элементами значений |
| Словарь | `<dictionary>` с элементами `<entry name="...">` |
| Итоговый документ | Корневой `<config>` с одним значением внутри |

Пустые массивы и словари записываются как пустые XML-элементы. Порядок
элементов массива и записей словаря сохраняется.

## 5. Примеры из разных предметных областей

В каталоге `examples/` находятся два полных примера:

1. `webserver.cfg` — конфигурация веб-сервера: порты, ограничения соединений,
   признаки функций и список узлов. Демонстрируются массив словарей и две
   константы.
2. `library.cfg` — конфигурация библиотеки: коды категорий, комнаты и
   статистика. Демонстрируются вложенные словари и повторное использование
   константы срока выдачи.

Так как строковые значения не входят в заданный язык, названия сущностей в
примерах представлены числовыми кодами.

## 6. Программный интерфейс и ошибки

Основные функции пакета:

- `parse_config(text)` в `config_converter.parser` разбирает строку, вычисляет
  константы и возвращает `int`, `list` или `dict` (`ConfigValue`).
- `to_xml(value)` в `config_converter.serializer` возвращает форматированную
  XML-строку с декларацией UTF-8.
- `convert_file(input_path, output_path)` в `config_converter.cli` выполняет
  полное файловое преобразование.
- `main(argv=None)` запускает CLI и возвращает код завершения; `argv` можно
  передать в тестах, по умолчанию используются аргументы процесса.
- `build_argument_parser()` создаёт и настраивает `argparse.ArgumentParser`.

Исключения из `config_converter.errors`:

- `ConfigError` — общий базовый тип ошибок конфигурации;
- `ConfigSyntaxError` — содержит `line`, `column` и список `expected`;
- `UnknownConstantError` — ссылка на ещё не объявленную константу;
- `DuplicateConstantError` — повторное объявление константы;
- `DuplicateKeyError` — повторный ключ словаря.

## 7. Тестирование и проверка качества

Запуск всех тестов на стандартном `unittest`:

```bash
python -m unittest discover -s tests -v
```

Проверка стиля и форматирования:

```bash
ruff check src tests
ruff format --check src tests
```

Тесты покрывают числа, пустые и непустые массивы и словари, вложенность,
объявление и вычисление констант, ошибки синтаксиса и семантики, XML, CLI и оба
примера. Всего в проекте 31 автоматический тест.

## 8. Структура репозитория

```text

run.sh                 кроссплатформенный для Unix запуск из исходников
```
